## Native execution and acceptance

Every fresh stage executes the unchanged original `count_protocol.py accept`
under the existing Linux native worker/controller seccomp guard. The CPU ceiling
is 43,200 seconds per forest; the wall ceiling is 43,500 seconds. Total memory is 2 GiB
split into 1,984 MiB for the worker and 64 MiB for the controller. Disk/log ceilings
are 256 MiB/16 MiB. These are budgets, not a measured completion estimate. No weaker
portable fallback is silently accepted.

The validator requires all 26 ordered roots, the entire selected leaf census,
exact candidate/source hashes, the original ordered 24 controls, exact native
statistics, typed successful exit, both actual guard files and unchanged source,
the real launch relation, complete bound stdout/stderr and equality between the
terminal JSON and the fresh native receipt. An observed unaccepted ledger is
written before validation; the separate accepted ledger can appear only after
the complete stage passes. Restored stages undergo the same complete review.

## Durable progress and reruns

Minute backups copy logs and source metadata, rather than copying thousands of
unchanged source files repeatedly. A stopped, accepted stage is immediately
exported as an immutable ZIP and SHA sidecar under:

`MyDrive/Berry-Esseen-end2end/n25-retained-b0/completed/<job-id>/`

The B1/B2 batches use their corresponding branch directories. A new session
reconstructs original inputs from the pinned public archive, then checks every
cached stage's ZIP safety, source binding, guard/capture chain and receipt before
skipping its numerical work. Original execution paths remain preserved and are
mapped during relocation. A bad, partial or incompatible cache is not acceptance.
An interrupted individual native forest must start its full replay again.

The final result ZIP includes the selected source capsules and the complete
fresh or revalidated stage evidence. A disconnected session may lack a final
batch ZIP; independently completed stage ZIPs still survive on Drive. Rerun the
same pinned notebook against the same Drive to recover them.
