This is a new, explicitly identified Linux BASIC execution protocol. It does
not acquire the support, kappa, Fourier analytic framework or attained-witness
premises. It does not prove a finite-index theorem or the all-index result.
No original numerical module was imported or evaluated during local
preparation and fixture tests. Actual numerical completion requires Colab.

The five-call owncaps transaction is cached atomically: its original inner
capture metadata binds absolute native cwd and command paths. Combining a
relocated old construct capture with a fresh replay would violate the
unchanged readback protocol. An interrupted owncaps transaction therefore
restarts fully. A fully completed transaction can be restored anywhere and
revalidated by mapping its one explicit originating task root; recorded
receipt or capture bytes are never rewritten.

Each resource stage exports complete upstream INITIAL and owncaps evidence
under `inputs/`, not only a PASS string or a hash. Its exact source-only
metadata derivation is recomputed during readback. The static/generated input
partition is fixed externally; no original mathematical source can be
reclassified as mutable. Every fresh ancestor byte, all 182 CAPS graph rows,
the original numerical resource payload, both parent bindings and the entire
fresh native receipt are checked. Only the top elapsed duration of the
resource acceptance output is ignored. A cached resource stage is reused only
when its upstream completed-stage hashes equal the currently selected INITIAL
and CAPS evidence.

`finite69_caps_evidence.validate_completed(stage)` revalidates one owncaps or
resource stage. `validate_batch(restored_batch)` revalidates all 19 stages and
their exact cross-stage bindings without importing numerical kernels.
The runner invokes this complete final validator before writing
`BATCH_VALIDATED.json` and exporting a successful batch. A failed final join
resets the conditional-completion flag and exports an incomplete result.

## Execution and transport contract

Every new owncaps/resource action uses the existing Linux BASIC process-group
supervisor with 43,200 seconds per-process CPU and sampled live-group CPU,
54,000 seconds external wall, 2 GiB per-process address space and sampled
live-group RSS, a 2 GiB sampled file quota and a 16 MiB log quota. CPU accounting
is not a cumulative whole-tree kernel quota. Memory sampling is not a cgroup
limit; this is not a Windows Job-equivalent or native-guard certificate.
Notebook45 INITIAL actions retain their unchanged original 512 MiB file quota
and otherwise the existing parent execution contract.

The outer cwd is the sealed capsule root, so all declared workspace-relative
outputs belong to the supervised working directory. Unchanged run.py gives its
child the original native directory. Every actual launch, supervisor result,
positive sample count, exact integer return code zero, stdout/stderr digest,
empty successful stderr and stopped whole-output copy is checked. Inner
run.py metadata is checked against its exact command, native cwd, interpreter,
contemporaneous complete input graph and actual captured result. The full
readback output, its complete graph extension into CAPS and all original
control inventories are bound to the actual outer captures.

The planner uses NumPy only for untrusted floating discovery. Its unchanged
child launch omits `-S`, so the Colab NumPy installation is available. Exact
acceptance uses the original exact modules. No local NumPy or original
mathematical kernel was run for this preparation. Dependency, platform or
resource failure remains an incomplete stage with bounded actual diagnostics.

Progress is streamed at least every 20 seconds; original stdout is forwarded
in bounded lines. Live logs/ledgers are copied to Drive every 60 seconds.
Complete stages are independently ZIP-exported with actual SHA256 sidecars.
Cache extraction rejects traversal, backslashes, duplicate/case-colliding
members, links, encrypted members, oversized members and missing ledgers
before extraction. Only complete, revalidated ZIPs can skip arithmetic. Final
session ZIP and sidecar are emitted on success or failure; completed earlier
stages remain reusable. Native acceptance, support acquisition, parent
acquisition, full finite6--9 and all-index flags remain false.
