# Independent n25 collector readback

Source-level review on 23 October 2026 of the new collector and notebook24 route. This is an independent readback of the collector/evidence implementations against the resource-to-contract mapper. No numerical leaf, INITIAL cover, resource proof or real exported proof mapping was evaluated in this review. No mathematical acquisition or completed n25 conclusion is reported.

## Scoped conclusion

No blocking source/schema/transport mismatch was found in the inspected route. The collector is a join of nine completed evidence jobs into seven selected conditional interfaces. It does not represent the remaining n25 regional union.

* `n25_count_evidence.validate_completed` returns the target, branch, exact design pin, accepted-capsule relative path, contract hash, acceptance-report path/hash and complete 26-root census expected by `n25_collect`. Source and acceptance clones both bind the original pinned design. The portable V14 preparation report is allowed only where the original preparation/acceptance copying actually places it.
* `n25_parent_evidence.validate_completed` returns the resource capsule as its original `new_root`, with separate resource proof/receipt hashes. The collector appends the original branch resource directory and filename correctly. The four stage artifact sets match `n25_parents.run`, including the exact fresh INITIAL proof and acceptance receipt consumed by both resource stages and the resource proof passed from construction to acceptance.
* Recorded POSIX original paths, explicit launch commands, working directories, native/controller launch files, captures and guard sidecars are revalidated after relocation. Original receipt, launch and capture bytes are retained. The count verifier's complete stdout JSON parsing matches the original native acceptor output; its statistics use the same leaf-status counters, maximum-score convention and maximum tree depth as native replay. The 24 control labels are read from the pinned acceptor AST without executing their functions.
* The collector binds the actual count contract and fresh resource proof bytes before calling the mapper. Its V14 reference is already included in the sealed count design; the reviewed final collector also explicitly compares that file with `target_spec`'s original V12 file SHA-256. This extra direct comparison was added following the review and was read back.
* The mapper's `branch` and `expected_p_interval` fields match the collector's actual uses. All four B4 closed p29 quarters and all three B3 closed panels have the expected ordered endpoints. Shared endpoints are retained.
* Every one of the two parent and seven count jobs is required for successful selected-interface status. Missing or rejected completed exports keep `selected_interfaces_verified=false`. An interface exception propagates to the wrapper's incomplete/error result and cannot create a successful partial join. The full n25, auxiliary24 acquisition, attained-contact acquisition and all-index flags remain false even on selected-interface success.
* Notebook24 calls the intended collector with the common durable root, uses an immutable full code commit, and describes its queued conditional scope. Its selected self-tests are infrastructure fixtures. The inherited ZIP extraction checks original ZIP sidecars, bounded ordinary members, containment, duplicate portable paths and complete unchanged extraction; it preserves the original task folder and evidence bytes.

The collector fixtures mock the numerical-evidence validators and mapper, so those tests alone do not establish a live end-to-end fresh-export result. This review supplements them with source compatibility inspection. The mapper's isolated 14 small synthetic test methods passed. A duplicate combined infrastructure test invocation was stopped after the publisher confirmed its own combined invocation was already running; no combined test outcome is claimed here.
