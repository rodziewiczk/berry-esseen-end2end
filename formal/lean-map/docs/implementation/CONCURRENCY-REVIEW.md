# Concurrency review: useful parallel work with a sequential baseline

Status: normative implementation review for the fresh end-to-end portfolio. It does not claim a measured speedup or an implemented whole-proof parallel runner. **Concurrency must never be a premise of mathematical correctness.** Every admitted proof route must still work at `-j1`; `--jobs auto` only changes scheduling of the same legal obligations.

## Legal independent work

| Work | Safe parallel unit | Required join |
|---|---|---|
| Ordinary COUNT | One complete freshly constructed and independently accepted forest for a frozen context; different forests can run in separate processes | Exact original-root/both-child/seam coverage plus current same-law resource-to-context license |
| Resource/Fourier families | Separate source-declared full stages, bands or panels only where an explicit checked aggregation rule exists | Coherent whole LOW/HIGH bounds, all finite pieces and infinite tails; no mixing incompatible coefficient choices |
| Small indices | Independent source-declared stages, retaining complete original native acceptors | All required cell/control/basis domains and separate analytic complements |
| Uniform49+ | Source-declared independent acquisition/auxiliary/local-comparison stages | All83 panels, actual-index uniformity, zero/positive-noise branches, strong46/base49 and smoothing |
| Transport/inventory | Independent immutable blob transfers and bounded byte/hash checks | All declared bytes/digests before an authenticated completion |

Fresh conditional COUNT for a **pre-frozen explicit context** can be calculated while independent resource acquisition runs: the numerical statement says that every law satisfying that context has the stated bound. Final applicability waits for the fresh same-law license. A downstream context whose actual values depend on an unknown quantitative U is not ready until its approved adapter materializes and freezes those values. Do not guess U or mutate an existing job.

AND dependencies require every selected whole output. OR alternatives require one explicitly licensed complete route. Selecting the sharp24 predecessor can avoid an unnecessary auxiliary24 recomputation; it cannot remove the required sharp20..24 finite providers. Racing alternatives does not license taking coefficientwise minima or joining parts from different laws, scopes, source epochs or resource corners.

The current next adapter supports one n6.B0.p61 forest. It must not manufacture 96 duplicate tasks to fill a machine. First parameterize genuine independent approved source-family contexts; run only ready work.

## Simple execution policy

Use isolated processes for CPU-bound Python rational arithmetic, construction and native replay. Bounded threads may serve independent file/network IO; they do not bypass the GIL for the rational kernels. A bounded thread pool may supervise already separate native child processes: the arithmetic is still process-parallel, so an additional process pool around every `Popen` is unnecessary. Move coordinator-side parsing/census CPU work to process workers only if its measured cost justifies that change. Keep the original native sub-process/thread accounting explicit. A job with its own pool/compiler is not charged as a single process by accident.

At every admission use the smallest applicable limit:

```text
slots = min(ready_count, configured_concurrency, available_CPU_slots,
            reserved_RAM_slots, scratch/log_slots, provider_quota_slots,
            remaining_budget_and_time_slots)
```

CPU/RAM/scratch reservations are held before launch and released only after owned processes/resources are observed stopped. Count queued/provisioning work that may start simultaneously. Leave room for OS/controller/shared read-only source data. An OS free-memory sample may reduce dispatch, but cannot increase it above the declared safe budget. Missing enforcement never becomes a fictitious hard RAM guarantee.

Maintain a reverse-dependency index and bounded ready heap; no complete DAG/event scan on every heartbeat. Use measured per-family costs for stable critical-path priority and longest-predicted-work-first bounded bundles. Unknown estimates remain unknown. Adapt only within frozen policy/caps, and always allow the controller to reduce to one worker. If the environment lacks a parallel capability, the sequential path remains supported rather than silently skipping work.

Protect verification capacity. Stop launching producers when the candidate backlog exceeds what remaining time/money can fully verify. A full worker queue is not proof progress. Near the deadline prioritize completing/checking already generated work; a timeout yields no final PASS.

## Immutable inputs and deterministic authority

Share only exact pinned read-only source/environment caches. Each attempt gets a private construction/verification directory, forest/checkpoint and logs. Source inventory checks must not race `.pyc` creation or a second writer; retain `-B/-S` where prescribed. Never let two processes modify one native forest or checkpoint.

Publish complete immutable bytes before fenced ledger completion. Exact task/attempt/generation and idempotency bind the authoritative result; a late worker can leave orphan bytes but cannot replace a newer result. Single-flight verification prevents duplicate simultaneous acceptance work for one exact key. The first authorized compatible definitive receipt remains the dependency anchor; timestamps alone do not trigger re-materialization.

Parallel reductions retain source order and exact rational/outward semantics. Whole roots/cells can finish out of order, but the assembler restores canonical root/left-first/term order. Native operational timestamps, directories and log bytes can differ. The equality requirement is the same mathematical statement, complete scope, trust assumptions and accepted conclusion, not identical wall time or every receipt byte.

Cancellation closes admission, revokes current authority, stops all owned process groups and reconciles resource lifetime before releasing liability. A process killed during construction or verification cannot publish acceptance. Original child-process and provider cleanup must be tested; direct-child termination alone is not advertised as complete hostile-descendant containment.

## Required conformance controls

These portfolio tests are required before enabling automatic multi-job scale; they are not claimed as performed by this document:

1. Run the same approved portfolio at `-j1` and `--jobs auto`. Both must cover identical required statements/scopes, obey the same analytic/trust/fresh policy and reach equivalent mathematical verdicts. Compare normalized claims and covers, not timestamps.
2. Randomize completion order and repeat identical keys. There is one authoritative compatible result, no duplicate coverage and no missing root/seam/tail.
3. Lose a lease during publication, kill a producer after a complete subtree, and kill a verifier before commit. Old attempts cannot complete; same-campaign resume preserves only validated work and does not reset the deadline.
4. Constrain CPU/RAM/IO to one slot. Automatic policy must fall back sequentially and preserve acceptance/rejection behavior. An OOM, log cap or unsupported source guard yields incomplete work, never EMPTY or PASS.
5. Saturate verifier capacity and lower available memory during execution. Backpressure reduces producer admissions without changing mathematical obligations or dropping controls.
6. Exercise dependency diamonds, whole-bound OR alternatives and quantitative-U materialization. No premature readiness or claim reuse across scope, source, strictness, environment or exact dependencies.

The existing SQLite adversarial tests already establish one claim winner and stale-generation rejection for the local pilot. That does not establish portfolio throughput, cloud behavior or numerical equivalence of a future auto scheduler.

## Performance evidence to collect

Measure native construction, complete replay/control time, interpreter/source hashing, charged peak memory, scratch/log/output bytes and transport overhead separately. Full fresh environment fingerprinting may dominate tiny forests; an immutable approved image/profile can be checked once per installation or bounded worker lifetime, while per-job source/context/candidate bindings remain mandatory. Do not cache old numerical results to optimize a fresh run.

A concrete observed bottleneck in the local native adapter is repeated interpreter-profile hashing: 1833 source/runtime files can dominate a tiny forest's arithmetic. A bounded batch may share one pinned runtime profile if the coordinator controls a stable read-only environment, every job retains exact per-capsule/context/checker/candidate bindings, and definitive acceptance is withheld until all owned processes stop and the complete runtime/source profile matches again. Before that final check, results are provisional. Drift or a crash without the final check quarantines the batch's acceptances; candidates remain untrusted and can undergo fresh acceptance. Check bounded groups rather than an unbounded campaign to limit recovery work. A before/after digest is not a proof against transient hostile file replacement; the declared execution profile must state its controlled-environment assumption.

No GPU, 96-worker target, SMT benefit or machine-count promise is assumed. Add complexity only for a measured bottleneck. The first useful baseline is a bounded process pool, a bounded IO pool, exact admission, backpressure and a sequential fallback.
